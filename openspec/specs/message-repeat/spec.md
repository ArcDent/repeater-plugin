# message-repeat Specification

## Purpose

让麦麦参与群聊复读：滚动窗口内同一文本被多人接龙达阈值后，按概率复读原文、发打断文本唱反调、或保持沉默；配套链终结防护与门禁冷却。作用对象是普通文本消息，与**表情回应**跟风能力并列。

## Requirements

### Requirement: 复读文本的消息资格

只有**纯文本消息**（消息仅含文本段且 trim 后非空）MUST 参与复读链累积。以下消息 MUST NOT 产出复读文本：含 @ 段、引用段、图片段、表情包段或其他富媒体段的消息；通知消息（`is_notify` 标记）；命令消息；文本长度超过 `repeat.max_text_length` 的消息；麦麦自己（`self_qq`）发出的消息。

#### Scenario: 纯文本消息进入复读链
- **WHEN** 群内一条仅含文本段、trim 后非空的消息到达
- **THEN** 该消息的文本参与复读链累积

#### Scenario: 含图片的消息不参与
- **WHEN** 一条消息同时含文本段与图片段
- **THEN** 该消息不产出复读文本，不参与累积

#### Scenario: 通知消息不参与
- **WHEN** 一条 `is_notify=True` 的通知消息（如戳一戳、撤回）到达
- **THEN** 该消息不产出复读文本

#### Scenario: 麦麦自己的消息不参与
- **WHEN** 发送者 QQ 等于 `self_qq` 的消息到达
- **THEN** 该消息不进入复读链累积

### Requirement: 宽松归一比对

两条消息的文本 MUST 在归一化后比对一致才算同一复读文本：去首尾空白、连续空白折叠为单个、大小写不敏感。**复读发送时 MUST 使用链内最后一条消息的原始文本**，不得使用归一化产物。

#### Scenario: 首尾空白不打散链
- **WHEN** 发送者 A 发 `草`、发送者 B 发 ` 草 `（首尾带空格）
- **THEN** 两条消息归一后一致，计入同一条复读链

#### Scenario: 大小写不敏感
- **WHEN** 发送者 A 发 `HHH`、发送者 B 发 `hhh`
- **THEN** 两条消息计入同一条复读链

#### Scenario: 复读发出原始文本
- **WHEN** 链内最后一条消息原文为 ` 草 `（含首尾空格）且复读出口命中
- **THEN** 麦麦发出的文本为 ` 草 ` 的原始内容，而非归一化后的 `草`

### Requirement: 滚动窗口与计数口径

复读链 MUST 在滚动时间窗口（`repeat.window_seconds`）内累积：统计口径默认仅计**不同发送者**人头（同一发送者的重复发送不增加计数）；`repeat.distinct_senders` 为 false 时 MUST 改为逐条消息计数。计数达到 `repeat.threshold` 时链达标，取得一次决策资格。窗口内未达标的历史消息随窗口滚动失效。

#### Scenario: 不同发送者先后接龙达标
- **WHEN** 窗口内 A、B、C 三个不同发送者先后发出归一后相同的文本，`threshold=3`
- **THEN** 复读链达标，取得一次决策资格

#### Scenario: 同一发送者重复发送不增计数
- **WHEN** `distinct_senders=true`，发送者 A 连发三条相同文本
- **THEN** 链上计数仍为 1，不达标

#### Scenario: 关闭去重后逐条计数
- **WHEN** `distinct_senders=false`，发送者 A 连发三条相同文本，`threshold=3`
- **THEN** 链上计数为 3，达标

#### Scenario: 窗口滚动使早期消息失效
- **WHEN** A 在窗口起点发过目标文本，此后超过 `window_seconds` 无同文本消息，B 再发该文本
- **THEN** A 的消息已随窗口滚动失效，链上仅 B 计 1

### Requirement: 三出口决策与发送

链达标后 MUST 掷骰**一次**，按三个**出口权重**（`repeat.weight_repeat` / `repeat.weight_interrupt` / `repeat.weight_silence`）归一化后的比例选中恰好一个出口，三出口严格互斥：**复读**（发送链内最后一条的原始文本）、**打断**（从 `repeat.interrupt_texts` 变体池随机取一条发送，MUST NOT 附带复读文本）、**沉默**（不发送任何内容）。权重 MUST 按非负数处理（负值与非法值按 0 计），三个权重全为 0 时 MUST 视为沉默且不掷骰。权重之间只有比例意义，单个权重的数值本身 MUST NOT 被当作概率。复读与打断 MUST 经**协议端直发**（`send_group_msg`）发出，MUST NOT 走主程序标准发送链；发送 MUST 在决策后延迟 `repeat.delay_min_seconds` / `repeat.delay_max_seconds` 范围内的随机时长执行，MUST NOT 使用表情回应域的 `behavior.delay_min/max`。发送失败 MUST 记日志且不重试。

#### Scenario: 复读出口命中
- **WHEN** 链达标且掷骰选中复读出口
- **THEN** 麦麦经协议端直发发出链内最后一条消息的原始文本

#### Scenario: 打断出口命中只发打断文本
- **WHEN** 链达标且掷骰选中打断出口
- **THEN** 麦麦只发出变体池中随机一条打断文本，不附带复读文本

#### Scenario: 沉默出口命中
- **WHEN** 链达标且掷骰选中沉默出口
- **THEN** 麦麦不发送任何消息

#### Scenario: 权重只有比例意义
- **WHEN** 三个出口权重同比例放大（如 85/15/0 改为 170/30/0）
- **THEN** 三出口的命中分布不变

#### Scenario: 权重全为零不掷骰
- **WHEN** 三个出口权重全为 0
- **THEN** 不掷骰，出口为沉默

#### Scenario: 发送前有自然延迟
- **WHEN** 决策出口为复读或打断
- **THEN** 发送在 `repeat.delay_min_seconds`/`repeat.delay_max_seconds` 区间内的随机时长后执行，不出现决策即发

#### Scenario: 复读延迟与表情回应延迟互不牵扯
- **WHEN** 表情回应域的 `behavior.delay_min/max` 被改动
- **THEN** 复读与打断的发送延迟不受影响，仍取 `repeat` 段自己的延迟区间

#### Scenario: 发送失败不重试
- **WHEN** 协议端直发失败（不可达或返回失败）
- **THEN** 记 warning 日志，不重试；已进入的冷却与链终结不受影响

### Requirement: 链终结

决策资格一经消耗（掷骰完成，无论出口为何）MUST 即刻链终结：按（群，复读文本）记录终结标记，标记 TTL（`repeat.chain_ttl_seconds`）内同文本的新发送者只续记录、MUST NOT 触发新的决策资格。标记 TTL 过期后，同一文本重新累积的新一轮复读 MUST 可再次取得决策资格。

#### Scenario: 决策后后续接龙不再触发
- **WHEN** 链达标已掷骰，D、E 随后发出同文本
- **THEN** 不产生新的决策资格，麦麦不再出声

#### Scenario: 沉默同样消耗资格
- **WHEN** 链达标掷骰出口为沉默，D 随后发出同文本
- **THEN** 不产生新的决策资格

#### Scenario: 标记过期后新一轮可触发
- **WHEN** 链终结标记 TTL 已过期，新一轮 A、B、C 接龙同文本达标
- **THEN** 新一轮取得决策资格，可再次掷骰

### Requirement: 门禁与冷却

复读功能 MUST 复用现有 `scope.group_whitelist`/`group_blacklist` 群白黑名单（黑名单优先）。`scope.ignore_senders` 名单内发送者的消息 MUST NOT 进入复读链。复读 MUST 使用独立于贴表情的群冷却（`repeat.cooldown_seconds`）：冷却期内链达标不消耗决策资格、不掷骰；冷却结束后同文本新发送者加入链可触发决策。沉默权重为 0 时，复读群冷却的压制期 MUST 是触发消息进入主程序消息链的唯一放行口。`plugin.enabled` 关闭时复读功能 MUST 整体停用；`repeat.enabled` 关闭时 MUST 仅停用复读（表情回应跟风不受影响），复读侧的 **planner 拦截**与两路**复读注入**随 `repeat.enabled` 一并停用，且 MUST NOT 受表情回应域 `context.enabled` 开关约束。

#### Scenario: 黑名单群不触发
- **WHEN** 黑名单群内出现达标复读链
- **THEN** 不取得决策资格，麦麦无动作

#### Scenario: 忽略名单内发送者不进链
- **WHEN** `ignore_senders` 内的其他 bot 连发相同文本
- **THEN** 其消息不进入复读链累积

#### Scenario: 独立冷却不与贴表情互相牵扯
- **WHEN** 麦麦刚完成一次复读（进入复读冷却），随后有表情回应上报命中跟风概率
- **THEN** 贴表情不受复读冷却影响，按表情自身冷却判定

#### Scenario: 冷却期内达标不掷骰
- **WHEN** 复读冷却期内链达标，冷却结束后同文本又来一个新发送者
- **THEN** 冷却期内不消耗决策资格；冷却结束后链因新发送者仍可取得决策资格并掷骰

#### Scenario: 沉默权重为零时冷却压制期仍放行触发消息
- **WHEN** `repeat.weight_silence=0` 且复读群冷却压制期内链达标
- **THEN** 不消耗决策资格、不拦截触发消息，该消息照常进入主程序消息链

#### Scenario: 复读独立开关关闭不影响表情跟风
- **WHEN** `repeat.enabled=false` 且表情回应上报命中跟风概率
- **THEN** 麦麦照常贴表情，不产生任何复读行为

#### Scenario: 复读开关关闭不拦截不注入
- **WHEN** `repeat.enabled=false`，一条本可触发复读出口的消息到达主程序消息链
- **THEN** 该消息不被拦截，也不产生任何复读注入，即使 `context.enabled` 为 true

### Requirement: planner 拦截

复读/打断出口命中时，插件 MUST 在主程序消息链上对**触发消息**（使复读链最终达标的那条消息）执行拦截：该消息 MUST NOT 写入主程序消息库、MUST NOT 进入主程序聊天上下文、MUST NOT 被 planner 决策。沉默出口 MUST 放行触发消息（麦麦保留对触发消息的正常反应权）。拦截动作 MUST 在同步决策段内完成，不引入异步等待点。

#### Scenario: 触发消息不被 planner 决策
- **WHEN** 复读出口命中，触发消息到达主程序消息链
- **THEN** 触发消息被拦截，planner 不会基于该消息发起回复（不出现复读与 LLM 回复双重发言）

#### Scenario: 打断出口同样拦截
- **WHEN** 打断出口命中，触发消息到达主程序消息链
- **THEN** 触发消息同样被拦截

#### Scenario: 沉默出口放行
- **WHEN** 沉默出口命中（或链未达标），触发消息到达主程序消息链
- **THEN** 触发消息正常进入主程序链路，planner 照常决策

### Requirement: 触发消息注入

planner 拦截生效的每一次复读/打断出口，插件 MUST 把**触发消息**的原文（发送者与文本内容）作为上下文消息写入麦麦聊天历史，补偿拦截造成的上下文缺失。该注入 MUST 无条件执行，与协议端直发成败解耦。注入 MUST NOT 串行叠加在发送延迟之前：注入与延迟 MUST 并发进行，使复读/打断的可见延迟为两者的较大值而非两者之和。两路复读注入的先后 MUST 保持「触发消息注入先于行为文本注入」，即麦麦聊天历史中「谁发了什么」始终早于「麦麦复读/打断了什么」。注入失败（聊天流查不到或主程序返回失败）MUST 记日志且不重试，拦截照常生效。注入内容 MUST 呈现发送者与消息文本，使麦麦能识别「谁发了什么」。

#### Scenario: 拦截后上下文仍有触发消息
- **WHEN** 复读出口命中，触发消息被拦截
- **THEN** 麦麦聊天历史中存在一条呈现该消息发送者与文本的上下文消息

#### Scenario: 注入不叠加在延迟之前
- **WHEN** 复读出口命中，且触发消息注入耗时短于发送延迟
- **THEN** 直发在延迟到期时执行，总耗时不因注入而增加

#### Scenario: 历史顺序为先触发消息后行为文本
- **WHEN** 复读出口命中且协议端直发成功
- **THEN** 麦麦聊天历史中触发消息的注入早于复读文本的注入

#### Scenario: 直发失败时触发消息注入仍执行
- **WHEN** 复读出口命中，触发消息注入已完成，随后协议端直发失败
- **THEN** 麦麦聊天历史中仍保留触发消息的注入，上下文反映「有人发了消息、麦麦没有动作」的事实

#### Scenario: 注入失败不回滚拦截
- **WHEN** 触发消息注入因聊天流查不到而失败
- **THEN** 记 warning 日志，拦截与直发照常执行，不重试注入

### Requirement: 行为文本注入

协议端直发成功后，插件 MUST 把发出的复读文本或打断文本作为上下文消息写入麦麦聊天历史，使麦麦知道自己发出了什么。直发失败时 MUST NOT 注入行为文本（上下文与事实一致：麦麦没有发出任何内容）。注入失败 MUST 记日志且不重试，不影响已完成的状态。

#### Scenario: 复读成功后麦麦知道自己复读过
- **WHEN** 复读出口命中且协议端直发成功
- **THEN** 麦麦聊天历史中存在一条呈现复读文本的上下文消息，后续 planner 唤醒时可见

#### Scenario: 直发失败不注入行为文本
- **WHEN** 复读出口命中但协议端直发失败
- **THEN** 麦麦聊天历史中不存在复读文本的注入消息

#### Scenario: 注入文案区分行为类型
- **WHEN** 行为文本注入发生
- **THEN** 注入消息可区分本次行为是复读还是打断

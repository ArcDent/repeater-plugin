# 反义与跟风两级决策，表情槽只存内存

两条行为分支的关系有三种可能语义：严格互斥、失败回落、各自独立。选**两级决策**——先掷「回应骰」按跟风概率决定是否贴表情（self 消息用独立概率）；回应骰掷中后，表情若命中反义映射，再掷「反义骰」决定贴相反表情还是贴同款，反义骰不中**回落跟风**。

严格互斥（早期版本）在命中反义映射的表情上掷不中即什么都不做，导致两类问题：一是反义概率越低，麦麦对高频表情的反应率越低，观感像选择性无视；二是「是否回应」与「回什么」被绑在一个骰子里，无法表达「先决定回应这个动作，再决定反义还是正义」的直觉。两级决策把回落限定在「已决定回应之后」——回应本身仍被跟风概率门控，不会让麦麦变得过于积极，同时保证命中反义映射的表情一旦回应就必有一个反应（反义或同款）。各自独立掷骰仍然排除：可能同时贴跟风和反义两个表情，与「一条消息一个表情槽」冲突。

表情槽（哪些消息麦麦已经贴过）与群冷却时间戳只存进程内存，不落盘。这两份状态的唯一作用是防重复贴和防自我循环，进程重启后丢失的代价上界是「对同一条消息多贴一次表情」，而落盘要引入 `ctx.paths.data_dir` 依赖、并发写、TTL 清理与损坏恢复，成本远高于它防住的损失。内存表按条数上界 + 时间 TTL 双重裁剪，避免长期运行涨内存。

## Considered Options

- **严格互斥**（命中反义映射只掷反义骰，不中即什么都不做）：反义概率越低麦麦反应越少，且把「是否回应」和「回什么」绑在同一颗骰子上。
- **失败回落**（先掷反义，不中再掷跟风）：与两级决策的区别是没有第一颗回应骰门控，命中反义映射的表情几乎总能得到反应，麦麦显得过于积极。
- **各自独立掷骰**：可能同时贴跟风和反义两个表情，语义自相矛盾。
- **表情槽落盘 JSON**：重启后不重复贴。但需要 `data_dir` 目录、写失败处理与损坏文件恢复，且插件热重载频繁，收益是「少贴一次表情」。

## Consequences

- 命中反义映射的表情在回应骰掷中后必有一个反应：反义骰中贴反义，不中贴同款。想让某个表情「命中后也完全不回应」，把它从反义映射里移除或调低跟风概率。
- `opposite.probability = 0` 等价于该表情回落到纯跟风；`opposite.enabled = false` 让所有表情回落到纯跟风。
- 反义分支也需要查「原作者是否是麦麦自己」（回应骰区分 self/other 概率），比严格互斥版本多一次 `get_msg` 查询（有内存缓存兜底）。
- 麦麦自己贴出的表情回应上报回来时，靠表情槽已占用来断环；表情槽是自我循环防护的最后一道也是唯一必需的一道（识别 bot 自身 QQ 号只是额外优化，取不到也不影响安全）。
- 进程重启或插件热重载后，冷却与表情槽清零，短时间内可能对重启前处理过的消息再贴一次。这是可接受的已知行为，不是缺陷。

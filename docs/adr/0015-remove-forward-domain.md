# 转发域从本插件整体删除，改由独立插件承担（0009–0014 转为历史记录）

本 ADR 补记已经执行的决定：2026-09-29 的 openspec change `remove-cross-group-forward`（已归档，commit `024edc8`，随 0.9.0 发布）把跨群转发域从本插件整体删除。当时的 design D5 定下「历史 ADR 不删，用新的退役说明标明它们不再是现行范围」，但这份说明一直没有落成 ADR，只散落在 AGENTS.md 的索引行与 CHANGELOG 里。本文补上，取代 0009–0014 的现行效力；这六份原文保留、不改写。

## Context

- 0.6.0–0.8.0 期间，本插件有第三个行为域「跨群转发」，即 ADR 0009–0012：
  - 0009：自动掷骰与请求转发两条路径并存；
  - 0010：协议端直发；
  - 0011：摘要就绪后触发，直发 / 决策双模式；
  - 0012：配置收敛。
- 2026-09-28 又出现两份草案：
  - 0013：调研在本插件内统一「按源消息 ID 投递」的重构范围；
  - 0014：提议把转发独立成插件「麦麦搬运喵」（`maimai-courier-plugin`），并改走主程序正常发送链，让转发信息经主程序历史同步自然进入上下文。
- 用户选择了 0014 的方向，在新项目里重做转发。于是本插件只剩一个问题：旧转发域是关掉，还是删掉。

## Decision

整域删除，不保留任何形式的转发入口：

- **代码**：
  - `forwards/` 整包；
  - `plugin.py` 里全部转发 Hook 与 Tool：`forward_detector`、`request_cross_group_forward`、`decide_forward_delivery`，以及三个 `maisaka.planner.*` Hook；
  - 自动 / 请求两条运行时、摘要轮询、决策票、群列表刷新、转发内容与留痕注入。
- **配置**：删除 `[forward]` 段与 `ForwardSection`，`plugin.config_version` 从 1.4.0 升到 1.5.0。旧 `config.toml` 里残留的 `[forward]` 键由 SDK 按未知键忽略，不为它们写任何兼容逻辑。
- **授权**：manifest 撤销 7 项转发专属能力，只保留两域实际消费的 4 项（由源码派生的比对测试钉死）。
- **不做**：不留 disabled 壳，不加隐藏开关，不给旧 Tool 建兼容别名，也不重定向到新插件。
- **保留**：复读与表情回应仍在用的共享设施按剩余调用方保留——协议端 HTTP、上下文注入、群流解析、后台任务管理。

## 原因

- **转发已有新的承担者。** 本插件回到「复读 + 表情回应」两个行为域，职责与名字一致。
- **只关不删留着三个后患：**
  - 新旧两套转发可能同时生效，同一批合并转发被处理两次；
  - manifest 继续申请 7 项已无用途的能力，属于过度授权；
  - WebUI 里留着一整段不再生效的配置，误导部署者。
- **0013 的方向已被取代。** 独立插件可以复用主程序发送链和内建历史同步，用不着在本插件里继续维护「协议直发 + 补注入」这条链；0013 研究的在本插件内重构转发投递，因此不再需要。

## Considered Options

- **配置关闭、代码保留**：改动最小，但上面三个后患一个都没消除，还得继续维护一整个不运行的域。弃。
- **旧 Tool 名保留为兼容别名，转调新插件**：两个插件之间多出一条运行时耦合，而新插件当时尚未验收。弃（design Non-Goals）。
- **按 0013 在本插件内重构转发投递**：已被 0014 的独立插件方案取代，不做。

## Consequences

- **0009–0014 的处理：**
  - 六份原文都保留，作为 0.6.0–0.8.0 行为与当时取舍的历史记录，不改写，也不再作为现行行为依据；
  - 0014 提议的「独立成插件」方向已由本决定落实，但它所述的具体设计（两参数工具、源群判断等）属于新插件，以新插件自己的文档为准。
- **部署切换**（design Migration Plan）：
  - 新旧两套转发不得同时启用；
  - 切换时先停旧功能，再开新插件；回滚顺序相反。
  - 0.9.0 发布时，新插件尚未验收、没有可部署版本，本插件不对它的行为作承诺。
- **线上数据**：旧转发域的持久化账本与日志不在清理范围，由部署者自行处理。
- **测试**：
  - 删除转发域时，新增了退役回归 `tests/test_forward_retirement.py`。
  - 2026-10-18 的收敛中，这个文件以及只为它存在的 tripwire 替身被删除。退役防护改由两条现行测试承担：
    - 源码派生的能力双向比对：任何转发能力调用、任何 `self.ctx.<x>()` 直调都会判红；
    - 组件面断言：组件恰为两个 `chat.receive.before_process` Hook。
  - 普通合并转发只是「含非文本段、不参与复读链」的一个输入样例，由复读域的非候选测试覆盖。

# 复读三出口改用归一化出口权重，取代配置层的双概率口径

## Context

复读的三出口决策（**复读** / **打断** / 沉默）自始至终只掷一次骰：`repeats.decide_repeat` 调一次 `roll()`，再按 `roll < probability` → 复读、`probability ≤ roll < probability + interrupt_probability` → 打断、其余沉默的累积阈值比较分流。spec、README 与 AGENTS.md 口径一致（「掷骰一次，三出口严格互斥」）。

但配置层把这一次掷骰暴露成两个各自独立的**概率**，且部署者真正会读的两处文案写的是两颗骰：`config.py:249` 的「达标后掷的第一颗骰」、`config.py:259` 的「复读骰未中后掷的第二颗骰……两颗骰都未中保持沉默」、`config.toml:49` 的「先掷复读，未中再掷打断」。两套口径给出的打断频率并不相等——默认 `0.6 / 0.15` 下，实现是打断 15% / 沉默 25%，文案描述的条件概率是打断 6% / 沉默 34%，差 2.5 倍。

双概率口径还留下一个只能靠文案解释的边界：两个概率之和 > 1 时沉默被挤掉、打断被静默截断。「概率」这个词本身在暗示两个出口可以各自独立调整，而它们实际在争夺同一根数轴。

## Decision

三出口用**出口权重**表达，配置层与决策函数同时改口径：

1. `repeat` 段新增三个整数字段 `weight_repeat` / `weight_interrupt` / `weight_silence`（`ge=0`，上限 1000，需要更细的刻度就整体放大），删除 `probability` / `interrupt_probability`。默认 **85 / 15 / 0**。
2. `decide_repeat` 一次掷骰，按归一化后的权重选中恰好一个出口；三个权重全为 0 时视为沉默、不掷骰（对齐旧的「两个概率都是 0 时不掷骰」）。互斥语义与「打断出口绝不附带复读文本」不变。
3. `plugin.config_version` 升到 `1.1.0`，迁移交给主程序：`plugin_runtime/runner/runner_main.py` 的 `_prepare_plugin_config_for_version_update` 检出版本升级后调 `rebuild_plugin_config_data(default_config, raw_config)`，以最新默认配置为骨架补新键、删废弃键、保留同名同类型的旧值，并写回 `config.toml`。
4. 表情回应域不动：那里的两级概率骰（**回应骰** + **反义骰**）问的是两个不同问题（要不要回应 / 回什么），不是三个互斥出口的选择，ADR 0002 的两级决策继续有效。

## Considered Options

- **只修文案、保留双概率**：零行为变更、零迁移，但「两个概率之和 > 1 怎么办」永远要靠文案解释，且「概率」一词继续暗示两个出口互不相干。
- **让代码跟随旧文案改成两颗骰**：打断从 15% 掉到 6%、沉默升到 34%，并把结构退回两次掷骰——与「三出口由一次掷骰选中」的领域模型直接冲突。
- **保留字段名、把值重新解释为权重**：不用迁移，但字段名 `probability` 与权重语义正面冲突，是更隐蔽的同一个坑。

## Consequences

- **默认 `weight_silence = 0` 意味着链一达标必出声**，触发消息也就必被 **planner 拦截**：麦麦不再有机会把复读文本当普通消息交给 planner 回复。唯一的放行口是复读群冷却的压制期（冷却期内链达标不消耗资格、不拦截，消息照常进主链）。要恢复「偶尔沉默」必须显式给沉默权重。
- 部署者手调过的旧概率值**不会**被迁移（键名变了）：升级后三个权重取新默认值，需要重调一次。这是选择重命名而非复用旧字段名的已知代价。
- 权重只有比例意义，UI 上不能显示成百分比；hint 需要举例说明「85 / 15 / 0 = 85% 复读、15% 打断、从不沉默」。
- 测试口径随之改（AGENTS.md「测试注意」同步）：「断言触发」的用例把目标出口权重拉满、其余归零；「断言不触发」的沉默用例从「两个概率归零」改成「沉默权重拉满、其余归零」——归零全部权重也落沉默，但那走的是「不掷骰」分支，证明不了掷骰确实发生过。
- `decide_repeat` 的参数签名变化（两个概率 → 三个权重），调用点只有 `plugin.py` 一处；纯逻辑层单测需要按新签名重写。
